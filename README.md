# اپ فارسی با Realtime Speech-to-Speech

این پوشه یک نمونهٔ قابل‌اجرا از اپ همراه سازمان و پروکسی WebSocket سروربه‌سرور برای OpenAI Realtime API است. صوت کاربر به PCM16 تک‌کاناله و ۲۴ کیلوهرتز تبدیل می‌شود و در تکه‌های زنده به Realtime API می‌رسد؛ خروجی PCM نیز هم‌زمان در مرورگر پخش می‌شود. مسیر جایگزین Whisper یا فایل صوتی کامل ندارد.

## اجرا

نیازمندی‌ها: Node.js 20+ و کلید API دارای دسترسی به Realtime API.

```bash
npm install
cp .env.example .env
```

مقدار `OPENAI_API_KEY` را در محیط سرور قرار بدهید؛ کلید را وارد HTML نکنید. سپس:

```bash
set -a && . ./.env && set +a
npm start
```

اپ روی `http://localhost:8787` در دسترس است. برای انتشار واقعی، HTTPS/WSS فعال کنید و `APP_ORIGIN` را دقیقاً برابر مبدأ سایت قرار دهید.

## صدا

فرانت‌اند به شکل خودکار برای بخش «خواهران» مقدار `selectedVoice = 'female'` و برای بخش «برادران» مقدار `selectedVoice = 'male'` می‌فرستد. سرور این مقدار را فقط به دو صدای مجاز نگاشت می‌کند و آن را در پیکربندی آغاز نشست Realtime قرار می‌دهد. پیش‌فرض‌ها `shimmer` و `echo` هستند؛ شناسهٔ صدا را با `REALTIME_VOICE_FEMALE` و `REALTIME_VOICE_MALE` می‌توان تغییر داد. Realtime API شناسه‌های صدا را ارائه می‌کند، اما برچسب زن/مرد رسمی برای هر صدا تعریف نمی‌کند؛ قبل از انتشار، صدای دلخواه را از نظر تناسب بررسی کنید.

## تغییر صفحه با tool call

Realtime tool `navigate_to_page` فقط صفحه یا پیام را هدف می‌گیرد. سرور رویداد function call را بی‌درنگ عبور می‌دهد؛ مرورگر با تابع `window.navigate_to_page(...)` URL داخلی را عوض می‌کند و نتیجه را به نشست برمی‌گرداند تا دستیار پاسخ صوتی خود را ادامه دهد. دسترسی‌های مدیریتی همچنان در سمت فرانت‌اند بررسی می‌شوند.

## اتصال کاربر و تولید واقعی

ورود موجود در HTML یک نمونهٔ محلی است و به‌تنهایی هویت را برای بک‌اند اثبات نمی‌کند. پیش از استفادهٔ عمومی، endpoint وب‌سوکت را به نشست ورود واقعی اپ متصل کنید، محدودیت مصرف و مجوز حساب را سمت سرور اعمال کنید و از WSS استفاده کنید. کد سرور API key را به مرورگر نمی‌فرستد.
